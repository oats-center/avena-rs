# Developing and deploying

The webapp is a SvelteKit 2 application written in TypeScript with Svelte 5,
styled with Tailwind CSS and daisyUI. It talks to NATS from the browser with
the `@nats-io` WebSocket client and decodes live messages with the
`flatbuffers` runtime. It has no backend of its own: every piece of data comes
from central NATS.

## Working on it

You need Node.js 18 or newer and pnpm.

```bash
cd webapp
pnpm install
pnpm dev            # http://localhost:5173, reloads on save
```

`pnpm dev --host 0.0.0.0` makes the dev server reachable from other machines
on the network.

| Path | Contents |
|---|---|
| `src/routes/+page.svelte` | Connect page: server address and credentials |
| `src/routes/labjacks/+page.svelte` | List of LabJack configurations |
| `src/routes/labjacks/plots/[asset_number]/+page.svelte` | Live plots and export for one configuration |
| `src/lib/components/` | `RealTimePlot` and `LabJackConfigModal` |
| `src/lib/nats.svelte.ts` | Connecting to NATS and reading and writing the key-value bucket |
| `src/lib/subjects.ts` | Subject names, matching `rust-ljm/src/subjects.rs` |
| `src/lib/flatbuffer-parser.ts` | Decoding live `Scan` messages |
| `src/lib/calibration.ts` | Volts to engineering units, matching `rust-ljm/src/calibration.rs` |
| `src/lib/exporter.ts` | The client side of the [export protocol](../reference/export-protocol.md) |
| `src/lib/sampler/` | FlatBuffers code generated from `rust-ljm/src/data.fbs`; do not edit |

`subjects.ts` and `calibration.ts` duplicate logic that also exists in Rust. A
change to subject names or calibration formulas has to be made in both places,
or the webapp will subscribe to the wrong subjects or show different numbers
from the exports.

## Building and running it for others

The app uses `adapter-node`, so a build is a small Node server:

```bash
cd webapp
pnpm install --frozen-lockfile
pnpm build                  # writes build/
node build                  # serves on 0.0.0.0:3000
```

`PORT` and `HOST` change the listen address, for example
`PORT=8088 node build`. Copy `build/`, `package.json` and the lockfile to
another machine and run `pnpm install --prod` there before `node build`.

Because all data comes from central NATS over the browser's own WebSocket
connection, the server only delivers the app's files. It can run anywhere
people can reach, with no special network access.

## API reference

The TypeScript modules under `src/lib` are documented in the [webapp API
reference](../api/webapp/index.html), generated by TypeDoc from the doc
comments. Svelte components and pages are not covered by TypeDoc; each has a
`@component` comment at the top of its file, which editors with the Svelte
extension show on hover, and they are described in [How the webapp
works](architecture.md).

To build the reference alone:

```bash
cd webapp
pnpm exec typedoc --options typedoc.json --out /tmp/webapp-docs
```

## Regenerating the FlatBuffers code

After a change to `rust-ljm/src/data.fbs`, from the repository root:

```bash
flatc --ts --gen-object-api -o webapp/src/lib rust-ljm/src/data.fbs
```

Regenerate the Rust side at the same time (see [Data
formats](../reference/data-formats.md#live-messages)).
